# 非追不可匯入檔

首頁「非追不可匯入檔」→ 選日期 → 收貨 → 製造 → 交貨。
每一步先核對數量與平台自編碼，勾選確認後下載 XLS，交給平台的「資料匯入」。
不會自動上傳、建立或刪除平台申報紀錄。

## 資料來源與範圍

- 收貨：未取消的採購品項，以送達日優先，未指定時採用供餐日；只有以 g 為基本單位的 snapshot 才自動換算公斤。個數類請補實際重量。
- 製造／交貨：當日有供餐、正數人數的學校菜單，彙整葷素與原料；餐別分開。原料採用菜單的本次配方覆寫，而非只讀共享配方。
- 小便當併入平鎮高中；新勢幼、信義幼併入各自國小。明原、中央大學幼兒園、廣豐依使用者指定排除。
- 產品碼、下游業者碼與已確認份重由私有服務設定 `FTRACE_PRODUCTS_JSON` 載入；不放入公開程式碼。未設定或設定無效時留空，必須補齊才可匯出。無已確認份重時保持空白。
- 交貨第一次載入時沿用已暫存的當日製造份數與重量，仍可改為實際交貨值。

## 編碼對照與草稿

原料名稱不等於平台自編碼，供應商碼也不等於原料規格碼。缺值時不得匯出。
可逐項填寫，或在「平台編碼對照」載入 JSON：

```json
{
  "materials": [{"name": "食材名稱", "code": "平台原料碼", "specs": [{"code": "平台原料規格碼", "supplier_name": "廠商名稱"}]}],
  "products": [{"name": "學校完整名稱", "code": "產品碼", "grams": 600}],
  "parties": [{"name": "供應商或學校完整名稱", "code": "交易對象碼"}]
}
```

名稱只做空白正規化後的唯一完全比對，不做模糊配對。多個規格碼需人工確認。
服務設定格式為 JSON 陣列，例如 `[{"name":"學校完整名稱","code":"TEST-P","customer_code":"TEST-C","grams":600}]`。名稱須使用合併後的學校名稱；產品碼與下游碼分開核對，不假設相同。只更新這個環境變數，不替換既有服務設定。
對照與按日期／類型區分的草稿存於同一瀏覽器 localStorage，可備份 JSON。
這些草稿不是共用的正式收貨／出餐實績；清除瀏覽資料會移除暫存。
重新載入草稿時只保留目前來源仍存在的項目，新增或刪除來源後須再次核對。

## 官方格式

欄位與工作表取自 2026-11-05 從平台下載的官方 ZIP：

- `https://ftraceindustry.fda.gov.tw/Document/收貨資料.zip`：餐盒業收貨資料（非依批號）
- `https://ftraceindustry.fda.gov.tw/Document/製造資料.zip`：餐盒業製造資料（非依批號）
- `https://ftraceindustry.fda.gov.tw/Document/交貨資料.zip`：餐盒業交貨資料（非依批號）

schema 固定於 `data/ftrace/schemas.json`；保留未使用的工作表及欄位標題，所有資料格使用文字格式。平台 24.14 版實際要求製造原料表名為「製造餐食原材料」，下載的舊範本「製造餐盒原材料」會被拒絕；依平台實際驗證結果修正。
每日申報方式為 `2`，日期 `YYYY/MM/DD`，流水號 `01` 起；最多 99 筆主資料。
這是平台一般「資料匯入」用的餐食製造業格式，非批號追溯格式，也不產生虛構批號。
交貨預設直接交給下游業者，無另行物流業者、自用或直接販售消費者。
若實際物流或交貨方式不同，須擴充表單後再匯出。

## 隔離與驗證

只有 `app.py` 增加一個模組匯入、首頁增加一個入口；既有計算程式未修改。
新服務只 SELECT，不建立資料表、不更新菜單／採購，不改 Supabase schema。
POST 沿用團膳 CSRF 保護，伺服器驗證必填欄位、日期、正數、精度與人工確認。
下載回應禁用快取。測試含完整回歸、實際瀏覽器三步驟下載和 XLS 讀回。
以平台實際匯入結果驗證相容性；僅本機可讀取不代表平台可接受。舊式 BIFF8 XLS 為必要格式，不能將 XLSX 改副檔名代替。

### 目前相容性驗證狀態

平台拒絕 XLSX；只有 Workbook stream 的 xlwt XLS 亦出現「External table is not in the expected format」。同內容經 LibreOffice 存成 Excel 97 XLS 後，收貨匯入顯示「處理完成」，並查到新增的 0.2 公斤毛豆仁測試紀錄。

補上 OLE 識別資訊後平台仍拒絕。最終定位到 xlwt 1.3 的 WriteAccess 紀錄：BIFF8 要求 XLUnicodeString，套件卻寫成舊式定長字串。`services/ftrace_xls.py` 依 [MS-XLS 2.4.349](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/231de348-d93c-4be3-a12b-a19173a45d69) 修正成無使用者名稱的合法字串，保持其他 BIFF 紀錄與資料內容不變；同時補上通用 OLE 識別資訊。伺服器不依賴 LibreOffice，識別資訊不含業務資料。

2026-11-05 已用實際叫貨／菜單來源的樣本，在平台確認三類「處理完成」且清單查到新增紀錄。公開文件只記錄驗證時間，不包含業務編碼與申報內容：

- 收貨 `verified_receiving.xls`：19:08:06 完成。
- 製造 `final_manufacture.xls`：19:13:36 完成。
- 交貨 `verified_delivery.xls`：19:11:48 完成。

另有較早的 LibreOffice 收貨測試。目前待使用者刪除確認，共四筆測試申報。失敗匯入僅留下上傳紀錄，未新增申報資料。
